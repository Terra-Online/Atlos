## 实施改动

### 让预算覆盖更多有效边界

区域跳跃提案原来可能把采样额度消耗在第一条长边上。现在轮流访问不同边界，先粗采样，再细化，并限制单个区域对的端点生成量。保留原有碰撞、支撑与运动学验证，预算耗尽仍表示覆盖不足。

方向子查询也获得少量区域链提案预算，从原有总预算中分配。这样先尝试可验证的多段连接，减少盲目前沿扩展，解决了旧点的超时问题。

### 一次扩展多个地面区域

前沿搜索一次最多返回四个不同地面连通区的有效动作，随后统一更新可达性。这样可以减少只发现一个动作就重建搜索状态的反复工作，也使不同中继方向有机会进入搜索。

### 避免候选变多后每个入口都搜不够

批量扩展使一个问题请求的入口数从 26 增至 73，原均分规则把每个入口预算从 307 压到 128，导致关键入口搜不出来。现在根据可用起点到入口的几何距离排序，每次入口搜索获得固定份额，并共用一份额外总预算。距离分数只用于排序。最终仍检查完整路线的可行性与资源消耗。

### 保留两种局部搜索结果

宽范围捷径搜索改变路线后，围绕原路线寻找局部改进可能错过新路线的机会。只切换到新路线又会丢失原来的有效候选。最终保留原路线的局部比较，再用剩余总预算比较改进后的路线，选择完整计时后更好的结果。

### 补齐终点事件证据

两个旧点已经从地面进入目标体积，却缺少显式终点事件。现在记录精确终点事件，并在体力调度拆分行走段、地面绕路替换后重新绑定事件的段索引与时间。

## 消融与未采用方案

| 试验 | 观察与决定 |
| --- | --- |
| 恢复旧枚举 | 可作为定位回归的对照，未作为实现方案采用 |
| 只缩小队列、改变包络计费或游标修订 | 004 仍不可达，未采用 |
| 每次扩展后重新运行区域提案 | 重复生成大量种子，004 仍失败且耗时约 78.9 秒，未采用 |
| 公平区域采样与方向提案 | 恢复超时点，但单独使用仍有不可达点 |
| 多区域前沿批量扩展 | 恢复 052、005，同时暴露入口预算被稀释的问题 |
| 入口排序与固定份额 | 恢复 004，路线代价降至约 30.1 秒 |
| 只围绕新 incumbent 做局部搜索 | 修复 038，但使 006 退化，最终采用双路线比较 |

学习算法方面，已有跨地图采集的 4666 个区域对、186640 个运动见证。当前生产求解器没有启用训练权重。这批数据支持后续按整张地图或 level 留出验证，并比较几何特征、控制特征及调度策略。训练结果需要通过完整路线回归后再用于搜索排序。
