# 卫星瓦片接入

标准瓦片保留在 `talos/public/clips/{region}/{z}/{x}_{y}.webp`；卫星瓦片使用独立的 `talos/public/satellite/{region}/{z}/{x}_{y}.webp`。两者共用地区坐标、瓦片尺寸和编号规则。

添加或更新文件后，在 `talos/` 执行 `pnpm data tile-coverage`。生成器分别更新 `tileCoverage.json` 与 `satelliteCoverage.json`；只在卫星覆盖中存在地表瓦片的地区显示卫星按钮。目录缺失的源代码检出使用已提交的覆盖快照。

VL 本次导出从 20000×20000 扩展到 24000×24000，在顶部、右侧各增加 4000 像素。为保持原有地图坐标，已对本地卫星瓦片做一次性编号补偿：0–3 级的 y 分别减去 1、2、4、8，x 不变；顶部新增瓦片使用负 y。图像内容未重新编码。再次直接复制同一批上游瓦片会覆盖此补偿，需先进行相同的编号转换。

后续 L/U 扩展由上游 `clip/splitMap.py` 按同一主图原点切片：L 贴主图左边缘，U 贴主图上边缘并左对齐。三级 L 使用 `x=-40…-1, y=-8…39`，U 使用 `x=0…39, y=-32…-9`；低级别按二倍缩放。上游已对齐的完整输出位于 `clip/output/satellite-vl/{z}`，可直接同步至本目录，无需再次减 y；旧 `input/preprocess/{z}` 仍是未补偿的主图切片。

`getTileResourceUrl(path, 'satellite')` 与 `getRegionTileCoverage(region, 'satellite')` 选择卫星资源，省略第二参数则保持标准地图。构建和发布同时处理两套独立目录及索引。

卫星仅显示 M 层。切换其他楼层临时使用标准地图，返回 M 恢复卫星偏好；在其他楼层选择卫星会返回 M。

`satellite.oem.re`、`satellite.opendfieldmap.org`、`satellite.opendfieldmap.cn` 以及主站的 `/satellite`、`/satellite/` 入口在预加载前启用卫星模式并返回 M 层，覆盖本机保存的标准楼层；之后仍可手动切换底图。无卫星资源的地区沿用标准底图并保留卫星偏好。

构建生成复用主站 bundle 的 `satellite/index.html`；Pages 包只携带该 SPA 入口，瓦片仍使用独立资源目录。短域 Worker 按地理位置把 `satellite.oem.re` 转发到对应卫星子域名，并保留路径和查询参数。线上还需绑定 `satellite.oem.re/*` 的显式 Worker route、`.org` 的 Pages 自定义域，以及 `.cn` 的 DNS／站点域名与证书；不使用 `*.oem.re/*` 通配 route。

配套 Bayes 的 CORS、认证来源与登录回跳默认白名单包含两个卫星主站子域名；若部署环境显式配置了 `CORS_ORIGINS`／`TRUSTED_ORIGINS`，发布时也需要在该配置中加入它们。

地区的 `coordZoom` 只保留像素坐标基准，最高原生瓦片层级从当前图层的 coverage 读取。帝江使用二级坐标基准和三级瓦片，避免地名、边界及已保存视野偏移；新增高分辨率瓦片不再需要修改原生层级配置。

楼层列表由标准 coverage 中实际有瓦片的楼层后缀推导，并沿用原来的显示顺序；逻辑瓦片尺寸统一为 200 CSS 像素，与图片文件的 500 像素尺寸独立。

地区配置不再声明矩形尺寸或边界偏移。瓦片图层和拖动约束使用完整 coverage，包含负坐标和超出旧矩形的新增瓦片；无需手动扩展边界。`initialCenter` 直接设置整数 `lat`、`lng` 启动坐标，不限制显示范围，已有历史视野仍优先恢复。

## Coverage 拖动边界

地图根据当前底图以及楼层叠加的 coverage 约束视野，保留宽、高均为视窗一半的连续瓦片区域，即一个象限的大小，允许跨瓦片接缝。若整个覆盖区域在最低缩放时也容纳不下该尺寸，则按相同比例缩减到地图能够提供的最大连续区域；不会因小地图而关闭保护。

正常停留边界内预留约 96 CSS 像素的弹性移动空间；鼠标、触控板和触屏越界时仍保留阻尼与回弹，但不能越过可见性底线。快速位移按整段路径裁切，不会直接穿过覆盖空洞。侧栏补偿沿用相同的 coverage 约束；旧视野、导航落点、底图／楼层切换和尺寸变化均重新核验。

连续缩放逐帧约束相机，触及可见边界后重设鼠标／捏合锚点，使后续缩放沿边界继续，反向缩放也立即响应。原生动画缩放使用相同的逐帧通路，避免只约束 CSS 动画终点而放过中间帧。每层 coverage 提前转换为最大连续矩形，分数缩放只做矩形运算，不重复扫描行区间。

`node scripts/check-coverage-drag.mjs [开发地址]` 用真实浏览器检查拖动过程。默认使用 `http://127.0.0.1:5174`；分别覆盖鼠标／触控板与触屏，并把逐帧检查结果写入 `/tmp/atlos-coverage-drag.json`。几何依据为有效瓦片覆盖，不分析瓦片内部透明像素；下载尚未完成的图片不属于可见性保证。

`node scripts/bench-coverage.mjs 修改前构建目录 修改后构建目录 输出目录 [开发地址] [pan|zoom]` 对比相同静态资源与 API fixture 下的生产包。两份构建应使用相同 `BUILD_ASSET_VERSION` 和依赖；脚本执行五轮交替桌面／4 倍 CPU 降速的底图拖动（默认）或空白处往返缩放（`zoom`），分别记录包体积、帧间隔、主线程任务耗时，以及开发入口中约束计算的批量耗时。点位筛选为空；测量不代表网络、真实移动设备或点位密集场景。原始性能报告保留在本地 `docs/perf/`，不纳入版本控制。
